Seedream 5.0 Lite is the high-resolution, lightweight tier of ByteDance's Seedream family: text-to-image, image-to-image and multi-image reference (up to 14 reference images) at 2K / 3K. The API uses the Volcengine Ark V3 images protocol: snake_case fields, and the request blocks until the images are ready and returns them directly, with no polling. SSE streaming pushes each image as soon as it is ready.

| | Volcengine Ark V3 | DreamTo |
|---|---|---|
| Endpoint | `POST /api/v3/images/generations` | `POST https://api.dreamto.ai/api/v3/images/generations` |
| `model` | Ark model ID | `seedream-5-lite` |
| API Key | Ark API key | API Key from the DreamTo console, in the `Authorization: Bearer` header |

## Parameters

| Field | Values |
|---|---|
| `prompt` | Required; keep it under about 300 Chinese characters or 600 English words |
| `image` | A string for one image or an array for several, up to 14; image links or `data:image/png;base64,<data>` (lowercase format), each up to 30 MB |
| `size` | `2K` / `3K` (1:1 output) or `WIDTHxHEIGHT` (default `2048x2048`); see size below |
| `response_format` | `url` (default) / `b64_json` |
| `stream` | `false` (default) / `true` (SSE; see Streaming below) |
| `sequential_image_generation` | `disabled` (default, one image) / `auto` (the model decides whether to create an image set) |
| `sequential_image_generation_options.max_images` | Maximum images in a set, 1–15 |

## Pricing

Billed at the model price shown in the console. Invalid requests and failed generations are not charged.

## Quick start

`$DREAMTO_API_KEY` is your API Key.

```bash cURL
curl -X POST "https://api.dreamto.ai/api/v3/images/generations" \
  -H "Authorization: Bearer $DREAMTO_API_KEY" \
```

```python Python
import os

import requests

URL = "https://api.dreamto.ai/api/v3/images/generations"
HEADERS = {"Authorization": f"Bearer {os.environ['DREAMTO_API_KEY']}"}

payload = {
    "model": "seedream-5-lite",
    "prompt": "An orange cat sitting on a windowsill watching the rain, watercolor style",
    "size": "2K"
}

result = requests.post(URL, headers=HEADERS, json=payload, timeout=600).json()
for image in result["data"]:
    print(image["url"])
```

## size

`size` takes one of two forms:

- **Resolution tier**: `2K` or `3K` (case-insensitive); the output is always 1:1. `4K` is not supported.
- **Pixel size**: `WIDTHxHEIGHT`, e.g. `2848x1600`; default `2048x2048`. The total pixels must be between 2560x1440 and 4096x4096 and the aspect ratio between 1/16 and 16. Up to 2048x3072 total pixels is generated and billed as `2K`, above that as `3K`, using the closest standard aspect ratio (`1:1` / `4:3` / `3:4` / `16:9` / `9:16` / `3:2` / `2:3` / `21:9`); the actual size is `data[].size` in the response.

## Streaming

With `"stream": true` the response is SSE (`text/event-stream`) with these events:

| Event | Meaning |
|---|---|
| `image_generation.partial_succeeded` | One image succeeded, with `image_index`, `url` (or `b64_json`) and `size` |
| `image_generation.partial_failed` | One image failed, with `image_index`, `error.code` and `error.message` |
| `image_generation.completed` | Final event, with `usage` |
| `error` | The whole request failed (e.g. timeout), with `error.code` and `error.message` |

The stream ends with `data: [DONE]`. A `: keep-alive` comment line is sent every 15 seconds while waiting; ignore it. Invalid parameters, insufficient balance and similar errors are returned as plain JSON before streaming starts.

## Timeouts

A request blocks for at most 10 minutes; images usually take 10–60 seconds, so set the client read timeout to at least 120 seconds. On timeout the API returns HTTP 504, and the job still finishes and is billed.

## Differences from the official API

- `model` is the DreamTo model name `seedream-5-lite`, not the Ark model ID.
- `output_format` and `watermark` are accepted but do not affect the output yet (the response shows the actual format); layer decomposition and `4K` are not supported.
- Errors use the DreamTo error envelope (see the error examples).
