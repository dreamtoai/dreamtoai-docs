`grok-imagine-image-2.0` is the newer xAI Grok Imagine image model, with better texture and 2K output. One model name covers both uses: `/v1/images/generations` for text-to-image and `/v1/images/edits` with reference images for image-to-image / editing, at the same price. The API is synchronous and returns the images directly, with no polling.

| Use | Endpoint | Model |
|---|---|---|
| Text-to-image | `POST /v1/images/generations` | `grok-imagine-image-2.0` |
| Image-to-image / editing | `POST /v1/images/edits` (with reference images) | `grok-imagine-image-2.0` |

The base URL is `https://api.dreamto.ai` and the API Key goes in the `Authorization: Bearer` header; text-to-image takes JSON, editing takes JSON or `multipart/form-data`.

## Endpoints

| Endpoint | Purpose |
|---|---|
| [`POST /v1/images/generations`](/en/api-reference/grok-imagine-image-2-0/create-image) | Create image |

## Parameters

| Field | Values |
|---|---|
| `prompt` | Required: what to generate or change |
| `n` | Number of images, default 1; 1 per request is recommended |
| `response_format` | `url` (default) / `b64_json` |
| `size` | `1024x1024` (default) / `1792x1024` / `1024x1792` / `2048x2048` |
| `resolution` | `1k` (default) / `2k`, equivalent to `size` |
| `aspect_ratio` | `1:1` / `16:9` / `9:16` / `2:3` / `3:2` / `4:3` / `3:4`; use instead of `size` |

## Pricing

Billed at the model price shown in the console. Invalid requests and failed generations are not charged.

## Quick start

`$DREAMTO_API_KEY` is your API Key.

<CodeGroup>

```bash cURL
curl -X POST "https://api.dreamto.ai/v1/images/generations" \
  -H "Authorization: Bearer $DREAMTO_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "grok-imagine-image-2.0",
    "prompt": "A futuristic city floating above a sea of clouds, soft morning light, cinematic",
    "n": 1,
    "response_format": "url"
  }'
```

```python Python
import os

import requests

URL = "https://api.dreamto.ai/v1/images/generations"
HEADERS = {"Authorization": f"Bearer {os.environ['DREAMTO_API_KEY']}"}

payload = {
    "model": "grok-imagine-image-2.0",
    "prompt": "A futuristic city floating above a sea of clouds, soft morning light, cinematic",
    "n": 1,
    "response_format": "url"
}

result = requests.post(URL, headers=HEADERS, json=payload, timeout=600).json()
for image in result["data"]:
    print(image["url"])
```

## Image-to-image / editing

Call `/v1/images/edits` and pass the reference images in one of these ways:

| Method | Form | Note |
|---|---|---|
| One public image | `"image": "https://.../a.jpg"` | The link must be directly downloadable by the server |
| One Base64 image | `"image": "data:image/png;base64,..."` | Use a full data URI, not bare Base64 |
| Several JSON images | `"images": ["https://.../a.jpg", "data:image/png;base64,..."]` | Links and data URIs can be mixed |
| multipart upload | `-F "image[]=@a.png" -F "image[]=@b.jpg"` | A single image can also use `-F "image=@a.png"` |

```bash cURL
curl -X POST "https://api.dreamto.ai/v1/images/edits" \
  -H "Authorization: Bearer $DREAMTO_API_KEY" \
  -F "model=grok-imagine-image-2.0" \
  -F "prompt=Blend the styles of the two reference images into a product shot" \
  -F "image[]=@reference-a.png" \
  -F "image[]=@reference-b.jpg" \
  -F "response_format=url"
```

## Tips

- One image per request: set `n` to 1 and send several requests when you need more images; it is more reliable.
- Use `url` to display images directly and `b64_json` to store or post-process them. Download returned links promptly.
- Clear, unobstructed reference images work best for style and background changes; for links that need a login, are on an internal network or are unreachable from mainland China, use a Base64 data URI instead.

## Differences from the official API

- Only `grok-imagine-image-2.0` is offered here; it is the only Grok image model with 2K output.
- `response_format` accepts `url` and `b64_json`; `url` is a DreamTo download link, so save the image promptly.
- Errors use the DreamTo error envelope (see the error examples of each endpoint).
